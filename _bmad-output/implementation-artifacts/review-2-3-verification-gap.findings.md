## Findings

- **The new AC3 integration test's DELETE-grant claim is not exercised by anything it does differently from the rest of the file.**
  - Changed surface: `releaseNomination`'s dependency on the `open_nominations` DELETE grant, and the integration test written to prove it.
  - Impacted site: the "Story 2.3 AC3 — releaseNomination deletes the claim row for real" describe block, whose own header comment states its purpose: "This is the only place `20260825000000_open_nominations.sql`'s DELETE grant is exercised — every other proof in this file either inserts or cleans up as the superuser `postgres` role, which would pass whether the grant existed or not."
  - Existing evidence: the new test's client is built identically to the file's `owner` client that the comment explicitly disqualifies — `new Client({ connectionString: LOCAL_DB_URL })` — where `LOCAL_DB_URL` defaults to `postgresql://postgres:postgres@127.0.0.1:54322/postgres`. CI pins the same value. `src/lib/shell/db.ts:37` shows the production write pool connects with exactly `SUPABASE_DB_URL` and nothing else.
  - Missing verification: an assertion that would fail if the DELETE grant on `open_nominations` were absent for the role `releaseNomination` actually runs as — i.e. a connection using a role distinct from the `postgres` owner.
  - Demonstration: if the migration failed to grant DELETE, this test would still pass, by the file's own stated criterion for why the other proofs in the file don't count.
  - Suggested shape: connect with a role distinct from the local `postgres` role to actually exercise privilege enforcement, or drop the grant claim from the comment.

- `releaseNomination` casts `event.payload as { readonly fantraxPlayerId: string }` with no runtime validation, and passes `payload.fantraxPlayerId` straight into the parameterized DELETE. This is inconsistent with its sibling in the same diff: `readClosedPlayerId` explicitly type-checks and rejects a missing/blank/non-string `fantraxPlayerId`, with the fold's own doc comment explaining why. None of the tests added for `releaseNomination` exercise a malformed or missing `fantraxPlayerId`; every case uses a valid string. `releaseNomination` currently has no production call site, so this is not yet a live regression path, but it is a real asymmetry the diff introduces between the two halves of the same release feature.
