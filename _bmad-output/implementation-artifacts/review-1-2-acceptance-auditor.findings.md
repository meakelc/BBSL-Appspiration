Verified locally: `npm run check` → 339 files, 0 errors, 0 warnings (AC 2 holds, including no unused `@ts-expect-error`); `npm test` → 7 files, 271 tests passed. `deferred-work.md`'s pure-core-boundary entry is marked resolved (AC 4 holds). Findings below.

- **The purity checker parses rather than stripping comments and string literals, and the deviation is unrecorded.**
  Violates the `<frozen-after-approval>` **Always** constraint (spec:22): "The purity walk recurses `src/lib/core/**` rather than reading a file list, *and strips comments and string literals first* so a doc comment naming `Date.now()` is not a false failure."
  Evidence: `scripts/check-core-purity.js` implements no stripping stage. Its header states the opposite approach — "**Why the TypeScript parser and not a regex** … Stripping comments and strings by regex then has to solve regex-literal detection and template interpolation" — and the implementation runs `ts.createSourceFile(...)` then walks the AST. The stated *purpose* of the constraint is met (and `tests/purity.test.ts`'s `describe('comments and strings are not code')` proves it), but the named mechanism is not what shipped. The spec's **Spec Change Log** (spec:83) is empty, and **Design Notes** (spec:93) still asserts "Comment stripping is load-bearing." Two smaller unplanned deviations *were* recorded in-place in this spec (`tsconfig.json` — "**not anticipated at planning time**", spec:74; `tests/constants.test.ts` — "**added**", spec:75), so the omission is inconsistent with the spec's own convention.

- **Two constants ship without the required PRD/AD source citation.**
  Violates Execution task spec:66: "declare every constant above as a named `const` **with a one-line comment citing its PRD or AD source**".
  Evidence: in `src/lib/core/constants.ts`, `INJURY_RESERVE_SLOTS` carries only `/** Injury Reserve Slots per Team. */` and `MINOR_LEAGUE_SLOTS` only `/** Minor League Slots per Team. Only a Minor League Eligible Player may fill one. */` — neither names a PRD section, FR or AD. Every other constant in the file does: `SALARY_CAP` ("PRD §3 glossary; §11"), `MINIMUM_BID` ("PRD §3"), `MINIMUM_INCREMENT` ("PRD §3 … AD-8"), `AUCTION_CLOCK`/`LEAGUE_CLOCK` ("PRD §3"), `FRESHNESS_WINDOW`/`STALE_WINDOW` ("AD-29"), `ACTIVE_BENCH_SLOTS` ("FR-37"), `YEAR_ALLOTMENT` ("PRD §3"), `GLOBAL_WRITE_LOCK_KEY` ("AD-6").

- **The new script's exported constant tables are not frozen, unlike the script the spec names as the shape to copy.**
  Violates the **Always** constraint (spec:22) "New scripts copy `scripts/check-pins.js`" together with Code Map spec:57, which identifies what to copy as "**frozen constants (line 27)**, pure `checkPins(inputs)` and `readRepositoryInputs()` exported, CLI at the bottom setting the exit code."
  Evidence: `scripts/check-pins.js:27` is `export const PINNED_PACKAGES = Object.freeze({...})` and `:44` is `const VERSIONED_FIELDS = Object.freeze([...])`. The new `scripts/check-core-purity.js` exports `FORBIDDEN_GLOBALS = new Set([...])` and `FORBIDDEN_MEMBERS = [['Math','random']]` with no `Object.freeze` — the `ReadonlySet`/`ReadonlyArray` JSDoc types are erased at runtime, so an importer can `FORBIDDEN_GLOBALS.delete('Date')` and silently disarm the gate. The other two elements of the copied shape (pure exported checker, thin CLI setting `process.exitCode`) are present. Note `constants.ts` itself does freeze (`YEAR_ALLOTMENT = Object.freeze({...})`).

- **The CI Deno step does not enforce AC 3's "no node_modules resolution" clause, and its command differs from the one the task specifies.**
  Bears on Acceptance Criterion spec:80: "Given a pull request, when CI runs, then `deno check` resolves and type-checks the core **with no `deno.json` and no node_modules resolution**", and on Execution task spec:70, which specifies `deno check src/lib/core/*.ts`.
  Evidence: `.github/workflows/ci.yml:76` runs `find src/lib/core -name '*.ts' -print0 | xargs -0 --no-run-if-empty deno check --no-config --no-lock`. `--no-config` discharges the "no `deno.json`" half; nothing in the invocation addresses the second half — Deno 2 discovers the repository's `package.json` from the working directory, and no `--node-modules-dir=none` or `--no-npm` is passed, so the AC's node_modules clause is asserted by the step's comment ("nothing here resolves a remote dependency: a core file that needs one is already a purity-gate failure") rather than enforced by the command. Separately, the command substitutes a recursive `find` for the specified `src/lib/core/*.ts` glob — a superset that is consistent with the recursion the spec requires elsewhere, but it is a change to the task's literal text with no Spec Change Log entry. The action pin (`denoland/setup-deno@22d081ff2d3a40755e97629de92e3bcbfa7cf2ed # v2.0.5`) and `deno-version: v2.9.5` match spec:70 exactly.
